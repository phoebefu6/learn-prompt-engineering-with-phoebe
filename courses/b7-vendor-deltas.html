Part 0

Why a whole session on vendors

Sessions 1-6 taught the shared core: clarity, structure, examples, grounding, chains, agents. Every vendor agrees on that core - then names it differently, places context differently, and ships per-model pages that change your prompts materially. Teams lose real weeks to this: one engineer quotes the OpenAI guide, another quotes Anthropic's, both are right, and the prompt ships wrong. Today we map the deltas and port TriageBot v4 across all three vendors to feel the portability tax first-hand.

Where they still genuinely disagree - few-shot stance and long-context placement - the disagreement reflects how each model family was trained, which is exactly why prompts do not port cleanly.

Real world

Meridian's week-long argument: a platform engineer insisted context goes "data first, question last" (he had read the Gemini docs); the Claude-side engineer insisted the same thing was "query after docs" (Anthropic's phrasing). They escalated to an architecture review before noticing they agreed. The third engineer, quoting GPT-4.1's "instructions at both ends", actually disagreed - and nobody noticed that.

Part 2 · per-model reality

The model-specific pages tour 7 min live

The biggest shift since 2024: every vendor now ships prompting pages per MODEL, not just per company - and they change your prompts materially. A prompt tuned for one generation can be actively wrong on the next. The habit this part installs: before shipping on a new model, read its page, then re-test.

LiveClaude's pages: Fable 5, Sonnet 5, Opus 4.83 min▶
  • Fable 5: a brief, clear instruction now beats a long enumerated list - over-specified prompts constrain it. It is steered to ground progress claims (no "done!" without evidence), and you set effort levels instead of coaxing depth with words.
  • Sonnet 5: the breaking change - temperature and top_p now return a 400 error. Adaptive thinking is the default; the old budget_tokens knob is gone in favor of effort. Prompts that shipped sampling params do not degrade, they crash.
  • Opus 4.8: has its own page too. The point is not memorizing each delta - it is that Anthropic maintains one page per model, and the deltas are real. Also live from Session 3: prefill returns a 400 on Claude 4.6 and later; the migration patterns replace it.
LiveOpenAI's GPT-5.1 page and Gemini 33 min▶
  • GPT-5.1: adds a none reasoning mode (a reasoning model that can skip reasoning - your model-class decision tree from Session 1 now has a toggle inside one model), personality shaping in the developer message, and first-class metaprompting: you can hand GPT-5.1 its own prompt and ask it to diagnose contradictions and ambiguities before you ship them.
  • Gemini 3: leave sampling defaults alone (the docs say it plainly), be precise and direct rather than persuasive or emotional, and control length with verbosity guidance. Long context stays data first, question last.
The habit that replaces memorizing this card Before shipping on a new model: 1) read its model-specific page, 2) re-run your eval set. Twenty minutes, every migration. Everything in this card will be stale within a year; the habit will not.
Part 3 · the dials

Sampling params: a history lesson 5 min live

Google's Boonstra whitepaper - still the best single PDF on prompting - devotes a whole chapter to temperature, top-K, and top-P. Learn the concepts: they explain why outputs vary and what "randomness" means mechanically. Then learn the 2026 reality: the vendors took the dials away.

LiveThe portability checklist: what to re-verify when you switch vendors3 min▶

Everything this session covered, compressed into the checklist you run on every migration:

SurfaceRe-verify
PlacementWhere do instructions and documents go? Claude: query after docs. GPT-4.1: both ends. Gemini: data first, question last.
DelimitersXML house idiom on Claude; markdown headers first on GPT. Re-check your tags survive.
Few-shot stanceKeep 3-5 on Claude, push more on Gemini, strip them for OpenAI reasoning models and re-test.
ParamsRemove temperature/top_p (400 on Sonnet 5, ignored by OpenAI reasoning, leave-default on Gemini 3). Map to effort/verbosity equivalents.
Tool-call formatEach API's tools field differs in schema shape and naming rules. Re-declare, never string-replace.

Self-studyOne card on open models (and one pointer past text)2 min read▶

Everything above assumed a hosted API. Run an open model - Llama and friends - and two more deltas appear. First, the chat format itself is yours to get right: Llama's chat template differs from hosted APIs, and a malformed template silently degrades output before your prompt is even read. Second, safety is a separate layer: hosted APIs bundle moderation; with open models you add it yourself, and Llama Guard is the standard classifier for filtering inputs and outputs. DeepLearning.AI's Prompt Engineering with Llama course covers both - self-study, not exam material.

And one pointer past text entirely: vision-model prompting (segmentation coordinates, diffusion negative prompts) is a real craft this course deliberately skips - see the course map's not-covered list.

Build-along

TriageBot goes multi-vendor ★ 22 min · build it with me

Meridian's platform team wants vendor optionality: TriageBot must run on Claude, GPT, and Gemini. Naive plan: copy the prompt three times. Real plan: port it properly, and write down every change you had to make. That list is the portability tax, and it goes in the repo next to the prompts.

Start from TriageBot v4 (Session 6): system prompt with agentic rules, lookup_order tool spec, policy manual, few-shot examples, JSON schema.

Write the Claude variant. XML delimiters for the manual and examples, query after the docs (ticket last), effort medium, no sampling params - Sonnet 5 would 400 the call.

Write the GPT variant. Markdown headers for structure, key instructions repeated at both ends of the long context, reasoning_effort set instead of any temperature, tools re-declared in OpenAI's schema.

Write the Gemini variant. Data first, question last - manual and ticket up top, the ask at the very end. All sampling defaults untouched. Consider one extra few-shot example; Gemini's docs push examples hardest.

Write down every delta. Placement, delimiters, example count, params, tool schema. That list is your portability tax - and your migration checklist for the next model generation.

TriageBot v4 - Claude variant (shown in full; deltas for the other two below)You are TriageBot, the support-ticket triage system for Meridian Retail. <policy_manual> [full returns + refunds policy, unchanged, cache-shaped] </policy_manual> <examples> [3 worked tickets with their exact output JSON] </examples> Agentic rules: - Keep going until the ticket is fully triaged; do not stop early. - If order status could change routing, use lookup_order. Never guess or invent an order status. - One-line plan before each tool call; reflect after each result. - At most 2 lookups per ticket, then set needs_human to true. Output: a single JSON object matching the schema in <schema> tags. Quote policy verbatim in the evidence field. <ticket> {{TICKET_TEXT}} </ticket> Classify the ticket above. (Query AFTER the docs - Claude's placement.)

Homework

Three things before Session 8 ◐ 30 min total

  • Port one of your own prompts to a second vendor using the portability checklist. Keep the delta list - bring it to Session 8, where it becomes eval cases.
  • Read one model-specific page for a model you actually use, end to end. Note one thing your current prompts do that the page says to stop doing.
  • Grep your codebase for temperature. Every hit is either a 400 waiting to happen (Sonnet 5), a silently ignored param (OpenAI reasoning), or a doc violation (Gemini 3). Decide the fate of each one.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · A teammate says "put it in the developer message". In Anthropic and Google terms, they mean...

One concept, three names: system prompt = developer message = system instructions. Half of cross-vendor arguments dissolve once the table is on the wall.

2 · Your prompt sets temperature=0.3. What happens across the 2026 model landscape?

The whitepaper-era dials moved: rejected on Sonnet 5, ignored by OpenAI reasoning models, leave-default on Gemini 3. Today you reach for effort and verbosity instead.

3 · Before shipping an existing prompt on a newly released model, the professional habit is...

Neither extreme. The core carries; the deltas (placement, delimiters, few-shot stance, params, tool format) need re-verification - and only your eval set proves what broke.
